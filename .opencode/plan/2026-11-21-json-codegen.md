# qi-json T8 — optional codegen (`cmd/qi-json-gen`)

**Date**: 2026-11-21
**Status**: done — T8a–T8e implemented and verified; the tool, its tests and the
fixture are in `cmd/qi-json-gen`.
**Related**: `docs/constitution.md`, `AGENTS.md`,
`.opencode/plan/2026-11-21-json-decoder.md` (T8), 
`.opencode/plan/2026-11-21-json-unmarshal-research.md` §5 A1, §8 Phase 8.

---

## 1. Why

The `marshal` decoder is reflection-free: struct binding is hand-written
compile-time accessor closures. That is the correct foundation, but the
boilerplate is the product defect — the research calls it "the boilerplate is the
product defect" (A2). Codegen removes it: a tool reads struct tags and emits the
`Schema` and `DecodeJSON` a user would otherwise hand-write.

It is **optional**: `marshal` is fully usable without it. T8 is an accelerator.

## 2. Decisions (agreed 2026-11-21)

- **D8.1 — Input, both modes.**
  - `qi-json-gen -type=Config [-type=Other] [pkgdir]` — the stringer idiom,
    driven by a `//go:generate` directive in the target file.
  - `qi-json-gen [pkgdir]` with no `-type` — scan the package for the marker
    comment `//qi-json:generate` on a type declaration and generate for each.
- **D8.2 — Field types, extended.** Beyond the exact types `marshal`'s
  constructors accept (`string`/`bool`/`int64`/`float64` and pointers), v1 also
  supports `int`, `int8/16/32`, `uint`, `uint8/16/32/64`, `float32` (and
  pointers), and same-package named types whose underlying type is one of these.
  Because `marshal` has no width-aware integer constructor (width needs
  reflection), the generator emits an inline conversion with a round-trip range
  check.
  *Extended later (2026-11-21):* a same-package named type whose underlying type
  is `string` or `bool` is also generated, as a converting closure with an
  `Encode`/`Empty` pair (and a `qiDecode*`/`qiEncode*` element pair for
  containers) — see `.opencode/plan/2026-11-21-codegen-named-string-bool.md`.
- **D8.3 — Output shape.** One file per package, default
  `<pkgdir>/zz_qi_json_gen.go`: per type an unexported `var <t>Schema` and
  `func (v *<T>) DecodeJSON(r *marshal.Reader) error`. The user's exported API is
  untouched.
- **D8.4 — Stdlib only.** `go/ast`, `go/parser`, `go/format`, `flag`, `os`,
  `path/filepath`, `strings`, `strconv`. **No `go/types`**: a source-based
  importer fighting module mode is fragile, and v1 needs only same-package type
  resolution, which a package-scope AST scan provides. This is a documented
  deviation from the research sketch (`§8 Phase 8` names `go/types`).
- **D8.5 — No runtime change.** The generator emits only calls to the existing
  exported `marshal` surface. The one addition is the package itself, which
  requires the constitution amendment in §5.

## 3. Generated code (sketch)

```go
// Code generated by qi-json-gen; DO NOT EDIT.

package example

import (
	"qi-json/marshal"
)

var configSchema = marshal.Struct[Config](
	marshal.String[Config]("name", func(v *Config) *string { return &v.Name }),
	marshal.Int[Config]("port", func(v *Config) *int64 { return &v.Port }),
	// int8: no width-aware constructor, so an inline closure with a round-trip check.
	marshal.Field[Config]{Name: "level", Decode: func(r *marshal.Reader, v *Config) error {
		k, err := r.Peek()
		if err != nil {
			return err
		}
		if k == scanner.KindNull {
			return r.ReadNull()
		}
		n, err := r.ReadInt()
		if err != nil {
			return err
		}
		if int64(int8(n)) != n {
			return qiRangeError(r, "int8")
		}
		v.Level = int8(n)
		return nil
	}},
)

func (v *Config) DecodeJSON(r *marshal.Reader) error { return configSchema.Decode(r, v) }
```

The generated file imports `qi-json/scanner` only when a custom closure needs a
`Kind`/`KindNull` test, and `math` only for a `float32` range check. A single
`qiRangeError` helper (and, as needed, element-decoder helpers) is emitted once
per file.

## 4. Field mapping

| Go field type | Emitted |
|---|---|
| `string` / `*string` | `marshal.String` / `marshal.StringPtr` |
| `bool` / `*bool` | `marshal.Bool` / `marshal.BoolPtr` |
| `int64` / `*int64` | `marshal.Int` / `marshal.IntPtr` |
| `float64` / `*float64` | `marshal.Float` / `marshal.FloatPtr` |
| `int`,`int8/16/32`,`uint`,`uint8/16/32/64`,`float32` (+ ptr), same-package named with that underlying | inline closure + range check |
| same-package named with `string`/`bool` underlying (+ ptr) | inline converting closure |
| `[]byte` (element `byte`/`uint8`) | `marshal.Raw` |
| `[]E` | `marshal.Slice` + element decoder |
| `map[string]V` | `marshal.Map` + element decoder |
| `[N]E` | `marshal.Array` with `func(v *T) []E { return v.F[:] }` |
| `any` / `interface{}` | `marshal.Any` |
| same-package struct `S`, generated | `marshal.Object[T, S]` + `sSchema` |
| unexported, or tag `json:"-"` | skipped |

Element decoders for `[]E`/`map[string]V`/`[N]E`: `(*marshal.Reader).ReadString`
/`ReadBool`/`ReadInt`/`ReadFloat` for the exact scalars; a generated `qiDecode…`
helper for extended numerics and same-package structs.

Tags: `json:"name"` sets the member name; `json:"-"` skips; `json:"-,"` names the
member `-`; `json:"name,omitempty"` names the member `name` and ignores
`omitempty` (it is an encode concern). An untagged field uses the field name.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Generated code drifts from the runtime API | Drift-guard test regenerates and byte-compares; the tool targets only exported `marshal`. |
| Round-trip range check is wrong for some width | Table tests at every boundary, signed and unsigned. |
| `go/ast` cannot resolve cross-package named types | v1 errors precisely; documented; `go/types` is a later, isolated upgrade. |
| Helper name collision in the user's package | Fixed `qi`-prefixed names, documented; the generator errors if a name is taken. |
| Generation is non-deterministic (map iteration) | Sort all emitted collections; the drift guard enforces it. |
| A same-package named `string`/`bool` type was not generated (D8.2 covers numeric underlyings only) | Resolved (2026-11-21): now generated as a converting closure; see `.opencode/plan/2026-11-21-codegen-named-string-bool.md`. |

## 8. Verification (handoff)

- **Files**: `cmd/qi-json-gen/main.go`, `gen.go`, `gen_test.go`;
  `cmd/qi-json-gen/internal/gentest/fixture.go`, `zz_qi_json_gen.go`,
  `fixture_test.go`.
- **Governance**: constitution v3.1.0 (Article VI third surface + Additional
  Constraints "Three packages"), `AGENTS.md` (layout, commands, naming),
  `Makefile` (`generate` target).
- **Generated-shape decisions recorded**: schema var unexported and named
  `<lowerT>Schema`; `DecodeJSON` delegates to it; helper names are `qi`-prefixed
  (`qiRangeError`, `qiDecode<Type>`) to avoid collisions; imports are computed
  (`qi-json/marshal` always, `qi-json/scanner` for a null peek, `math` for a
  `float32` bound) and sorted.
- **Behaviours worth knowing**:
  - `omitempty` is ignored (an encode concern); `json:"-"` skips; `json:"-,"`
    names the member `-`; an untagged field uses the field name.
  - Unexported fields are always skipped.
  - A numeric field is range-checked by round-trip: `int64(T(n)) != n` for a
    signed `T`, with a leading `n < 0` for an unsigned `T`; `float32` against
    `±math.MaxFloat32`. A violation is a `*marshal.Error`/`KindType` with the
    target type as `Want` and `"number out of range"` as `Got`.
  - **Documented limitation**: `uint`/`uint64` are decoded through
    `ReadInt`/`int64`, so a JSON number above `2^63-1` is rejected even for a
    `uint64` field. `Raw` returns the value's exact literal bytes (a JSON string
    includes its quotes).
